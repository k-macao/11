Why

这条工作流没有 schedule 触发器。它不会在凌晨自己醒来，不会在你休假时刷屏，也不会因为某个源挂掉而反复报警。

推送的时机由人决定 —— 开盘前、收盘后、突发行情时。Actions → Run workflow，仅此一个入口。

Config · 05 05 / 08
Secrets vs Inputs

配一次，跑很多次

A · Repository Secrets
PUSHPLUS_TOKEN

必填。PushPlus 官网获取，填入 Settings → Secrets and variables → Actions。

PUSHPLUS_TOPIC

选填。填写群组编码即群发；留空则只推给自己。

缺少 token 时工作流第 3 步直接失败，不会发出空推送。

B · Dispatch Inputs
headline_count

金融要闻条数。默认 8，上限 15，超出自动收敛。

quote_count

行情指标数量。默认 12，即全量符号表。

两个入参都是可选的，直接点 Run workflow 即走默认值。

Resilience · 06 06 / 08
Failure Modes · Designed Degradation

坏掉的时候怎么办

Case 01
行情源超时

单个符号 12 秒超时后被 Promise.allSettled 丢弃，其余指标照常成表。

Case 02
新闻源不可用

要闻区落为提示文案，行情表仍然推送，不阻断整次投递。

Case 03
两源同时失效

抛错终止，明确拒绝发送空白报告 —— 宁可不发，不发噪音。

Case 04
重复触发

并发组 manual-finance-pushplus 串行排队，cancel-in-progress 为 false。

scripts/push-finance-brief.mjs timeout-minutes: 5
